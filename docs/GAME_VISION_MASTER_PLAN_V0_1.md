# Pixel Nations — Game Vision Master Plan v0.1

Status: ACTIVE PRODUCT DOCTRINE
Date: 2026-06-19
Owner: ChatGPT as Product Lead / Creative Director / Technical Strategist / Game Director

## One-Sentence Vision

Pixel Nations is a living interactive strategy atlas where one small land can grow into a city, a nation, and eventually an empire.

## Final Product Direction

Pixel Nations should not be a purely descriptive text strategy game.

Pixel Nations should also not try to become a full real-time strategy game or a full 3D city-builder too early.

The best final direction is:

# Living Atlas Strategy Builder

A hybrid of:

- interactive world map
- growing settlements
- strategic resource/state systems
- visible trade routes and influence
- symbolic armies and migration
- animated map feedback
- narrative consequence panels
- long-term empire progression

The player should make strategic decisions through readable panels, but the world should visibly respond on the map.

## Core Fantasy

The player starts with one land.

That land becomes:

land → settlement → city → nation → empire

The emotional promise is:

> I started with one place. I shaped it. I watched it grow. It became mine.

## What The Player Should See

Over time, the map should show:

- claimed lands
- settlement markers
- city growth states
- nation borders
- empire influence zones
- trade routes
- caravans or ships as symbolic moving tokens
- migration flows
- patrols / armies / banners
- resource overlays
- unrest or prosperity signals
- construction or development pulses
- event markers
- frontier tension zones

This should be symbolic and elegant, not a heavy simulation of every person.

## Living World Rule

Do not simulate every villager individually.

Create the feeling of life through:

- animated routes
- icon movement
- map overlays
- city-state visual upgrades
- event pulses
- changing settlement cards
- sound/animation later if appropriate
- visible consequences after decisions

## Final Gameplay Shape

The final game should have two layers:

## 1. The Map Layer

This is where the world feels alive.

It shows:

- territories
- cities
- routes
- movement
- influence
- conflict
- prosperity
- events

## 2. The Decision Layer

This is where the player chooses.

It contains:

- settlement development
- trade decisions
- alliance decisions
- doctrine decisions
- nation policy
- empire strategy
- later military/diplomatic/economic choices

The map should show consequences of the decision layer.

## What Pixel Nations Is Not

Pixel Nations is not:

- a purely text-based game
- a spreadsheet game
- a full RTS
- a full city-builder with hundreds of buildings
- a simulation of every individual person
- a blockchain/NFT/wallet-first project
- a pay-to-win land speculation product
- a massive multiplayer game before the core loop works

## Realistic Development Phases

### Phase 1 — Demo Spine

Status: done / baseline.

Goal:
Show land → settlement → nation → empire path.

### Phase 2 — Local Core Engine

Status: started with Core Engine v0.3.

Goal:
Make land and settlement state change through decisions.

### Phase 3 — Visual Gamefeel Engine

Goal:
Make decisions feel alive through icons, graphic action cards, animation, and better visual feedback.

### Phase 4 — Living Map Layer

Goal:
Show trade routes, migration, influence, city growth, patrols, and symbolic movement on the map.

### Phase 5 — Nation Economy and Policy Layer

Goal:
Connect settlements, trade, alliances, doctrine, prosperity, stability, and population pressure.

### Phase 6 — Empire Conflict and Influence Layer

Goal:
Add symbolic military, conflict pressure, regional influence, and rival powers.

### Phase 7 — Persistence / Accounts

Goal:
Introduce player accounts and saving only when the game has enough return value.

### Phase 8 — Human Players / Testing / Registration

Goal:
Use humans only when there is meaningful ongoing gameplay and engagement to measure.

## Near-Term Direction

The next major product direction after Core Engine v0.3 should be:

# Visual Gamefeel Engine v0.4

This should improve:

- graphic presentation of settlement development
- action icons
- visible stat changes
- animated feedback after actions
- better settlement/state visualization
- stronger “living world” emotion

But it should be scoped carefully and not become a full art overhaul.

## Strategic Priority

Current priority order:

1. Preserve working demo baseline.
2. Build simple real engine loops.
3. Make those loops visually satisfying.
4. Move consequences onto the map.
5. Add persistence only when return value exists.
6. Invite humans only when the game can retain them.
