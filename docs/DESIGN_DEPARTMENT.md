# Pixel Nations Design Department

## Purpose

The Design Department protects the visual quality, clarity, and emotional identity of Pixel Nations.

It must be used whenever the project touches:
- world map design
- visual identity
- UI polish
- first-time user clarity
- premium/fantasy atmosphere
- anything that has already failed visually after multiple implementation attempts

Pixel Nations should not rely on code iterations alone for visual quality.

## Virtual Team

### Art Director
Owns the overall visual taste and quality bar. Decides whether the work feels premium, believable, and emotionally aligned with Pixel Nations.

### UI Designer
Owns interface clarity, hierarchy, spacing, readability, and CTA presentation.

### Cartographer / World Map Designer
Owns map logic, landmass credibility, region layout, terrain rhythm, ownership readability, and the relationship between full world and playable sectors.

### Game UX Designer
Owns the player journey: land → settlement/city → nation → empire. Ensures that visual design supports the game fantasy instead of distracting from it.

### Brand Designer
Owns tone, typography feel, visual consistency, naming, and whether the product feels distinctive rather than generic.

### Frontend Visual Lead
Owns implementation feasibility. Translates art direction into CSS/component constraints without broad refactors or visual drift.

## When This Department Must Be Invoked

Invoke the Design Department before:
- any World Map v8 implementation
- another visual redesign sprint
- changing global style direction
- introducing new map metaphors
- preparing pitch/deck visuals
- evaluating whether the demo is visually ready for outsiders
view Method

Every visual task should be judged by:
1. Manual reaction, not screenshots alone.
2. Product clarity, not decorative density.
3. Premium strategic fantasy feeling.
4. Whether the user understands what to do next.
5. Whether the visual direction supports the core promise.

## Anti-Loop Rule

If a visual feature fails after multiple implementation attempts, stop coding.

Do not ask Cursor for another version until there is:
- an art-direction brief
- a reference board
- an acceptance rubric
- a clear implementation boundary

Cursor is executor, not art director.
