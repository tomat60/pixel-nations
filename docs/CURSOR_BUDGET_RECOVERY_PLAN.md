# Cursor Budget Recovery Plan v0.1

Status: ACTIVE  
Owner: Cost-Control Lead / Product Lead  
Purpose: prevent visual iteration loops from consuming paid Cursor budget.

## Current Lesson

A small landing map/frame problem consumed too much Cursor attention and too much paid budget. This cannot become the default.

## Operating Rule

Cursor is reserved for high-leverage implementation, not for open-ended visual search.

## Default Tool Order

1. ChatGPT strategic diagnosis.
2. Zero-Cursor source/evidence collector.
3. Deterministic patch package.
4. Terminal-run package.
5. Visual/public QA review.
6. Cursor only if deterministic patch is unsafe.

## Cursor Allowed

Cursor is allowed when:
- task is implementation-heavy,
- exact scope is known,
- prompt passed Prompt QA,
- stop condition is measurable,
- rollback is obvious,
- cost risk is accepted.

## Cursor Blocked

Cursor is blocked when:
- the problem is unclear,
- the issue is visual polish without hard constraints,
- the assistant has not inspected source/evidence,
- a direct patch can be created safely,
- the task is docs-only,
- the task is QA/merge/handoff automation.

## Emergency Reserve

Keep at least 20% of monthly Cursor budget untouched for high-value project-critical work.
